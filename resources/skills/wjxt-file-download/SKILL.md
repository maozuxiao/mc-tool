# 鸿翼文件系统：搜索与原始文件下载

## 适用范围

用户在对话里提到「文件系统 / 鸿翼 / 弘毅 / 企业内容库」，或要求按关键词找一份文件、把某个文档下载到本地时，用本技能的两个工具完成：

| 工具 | 作用 |
|---|---|
| `wjxt_search` | 关键词检索（文件名 + 正文内容），返回编号清单：编号 / 文件名 / 扩展名 / 字节数 / **修改时间** / **版本号** / 目录路径 / `fileGuid`，以及给人点的 **`previewUrl`（预览）/ `downloadUrl`（下载）** |
| `wjxt_download` | 按 `fileGuid` 下载**原始文件**到指定目录（不转码、不改格式，字节数与服务器一致）；回报每个文件的**文件头类型**与**字节数是否与期望一致** |

> 两种「拿到文件」的方式分工：**清单里的「预览」/「下载」链接给用户自己点**（预览在应用内窗口查看、下载弹「另存为」）；
> `wjxt_download` 只在**用户明确要求「存到某个目录」**时用（它由 AI 直接写盘并做校验）。

> 查询串不带范围前缀 `(filepath:(1) OR masterfilepath:(1))` —— 实测带上它会把结果筛成空（HTTP 200 但 0 条）。
>
> **检索参数速查**（完整说明见 `wjxt_search` 工具定义，两处保持一致）：
> `sort:'time'` 按修改时间倒序（**问「哪个最新」就用它**；本部署服务端 `modifyTime` 排序会**静默返回空集**，
> 工具遇到 0 条会自动改回「相关度 + 本地排序」并在 `note` 里说明，直接看结果即可）；
> `from` 翻页（**`total` 大于返回条数时必须翻**，返回带 `hasMore`）；
> `mode` 控制匹配方式（`word`/`contains`/`exact`）；`query` 可传 ES 查询串限定字段与时间区间
> （字段：`filename`/`filecontent`/`extName`/`creatorName`/`modifyTime`）。
> **`filepath` / `masterfilepath` 只能用于筛「已召回」的结果，不能用来检索目录** ——
> 实测 `filepath:(版本火车V2.5.1)`、`filepath:(ADPlus2.0)` 都是 `total 0`；要按目录找就点 `folderUrl` 浏览。
>
> 注意：**通配符大小写敏感**（实测 `*RED*` 匹配不到 `Red.png`）；`mode=contains` 时工具已自动 OR 大小写变体。

## 版本查询方法论（版本类问题的唯一查法；skill 2.2.0 起取代原「硬性检查项」）

### 0. 一句话原则

**检索只能返回与关键词相似的结果样本，不能列出全部版本。**
没搜到某个版本，只说明这次检索没有召回它，不代表它不存在。
凡问题里出现「最新 / 最高 / 所有版本 / 有没有更高的」，先按下面的 SOP 走完，再决定措辞。

### 1. 四个已证实的坑（每条都是实际踩过的）

| # | 坑 | 实证现象 | 正确做法 |
|---|---|---|---|
| 1 | **目录名和文件名不一致** | 目录名 `版本火车V2.5.1-Standard Version V2.5.1`，里面文件名却是 `火车V2.5.1-ADplus2.0-ReleaseNote-中文-260930.docx`（少「版本」二字） | 关键词里**必须带版本号本体 `V2.5.1`**，不要只带「版本火车」这类目录用词 |
| 2 | **`filepath` 字段不可靠** | `query: filepath:(版本火车V2.5.1)` → `total 0 / hasMore false`；`filepath:(ADPlus2.0)` → 同样 0 | 目录名**不是检索对象**。只能从文件命中结果里反向看 `folderPath`，或直接点 `folderUrl` 浏览目录树 |
| 3 | **`total`/`hasMore` 是召回集范围，不是全库范围** | 两次检索都返回 `total 50 / count 50 / hasMore=false`，据此断言「最高 V2.4.1」，而 V2.5.1 早已存在 | `total` 只是本次召回条数；即使 `hasMore=false` 也**不能**推出「库里只有这些」 |
| 4 | **`sort:'time'` 只在召回集内排序** | V2.5.1 的 ReleaseNote 修改时间（2026-10-14）最新，却完全没进召回集，所以按时间排序根本轮不到它 | 排序是**事后**动作，补不回被漏召回记录。排序结果与版本结论无关，版本新旧只认版本号 |

### 2. 标准作业流程（SOP）

**Step 1｜先取版本号锚点**
- 用户已给出具体版本号（如「找 2.5.1」）：直接跳到 Step 2，用该版本号检索。
- 用户只说「最新 / 最高」：先跑 Step 2、3 收集候选版本号，**不要先下结论**。

**Step 2｜版本号维度检索（必做，独立于产品名检索）**
```
query: filename:(<版本号> AND <产品词>)
例：filename:(V2.5.1 AND ADplus2.0)
```
- 命中后**翻页看完**：`total > count` 就用 `from` 翻到 `hasMore=false`。
- 若该查询 `count 0`（分词差异导致版本号被切开），退回 `keyword: <产品词> <版本号本体>`
  （如 `ADPlus2.0 V2.5.1`），**不要把 0 条当成「该版本不存在」**。
- 这条检索的翻页**不计入「每次对话最多 2 次 wjxt_search」的限制** —— 那是验证动作，不是换词碰运气。

**Step 3｜产品维度检索，收集全部候选版本号**
```
keyword: <产品词> 版本火车 ReleaseNote
例：ADPlus2.0 版本火车
```
把结果里出现的**所有版本号**抽出来去重，形成候选集（如 `V2.1 / V2.2 / V2.2.1 / V2.3 / V2.4 / V2.4.1 / V2.5.1`），
按版本号分段比较排序（`V2.4.1 < V2.5 < V2.5.1`，**不要按字符串排序**）。

**Step 4｜对候选集最高版本再验一轮**
- 拿候选集最高版本向上试一档（`V2.5.1` → 再搜 `V2.5.2`、`V2.6`；或直接搜 `V2.5`、`V2.6`、`ReleaseNote`）。
- 目的是发现「跳号存在但没进候选集」的版本 —— **这正是本次漏掉 V2.5.1 的直接原因**。

**Step 5｜产品线归属核对（防同名版本号混入）**
对每个候选，看 `folderPath` 判断归属，**只有同时满足才算目标产品的通用版**：
- 路径包含目标产品目录（如 `...\ADPlus2.0\`）；
- 路径包含 `Standard Software 标准软件` / `Standard Version`；
- **排除**：带客户名或项目号的定制目录（如 `228752 新西兰`、`86041`）、
  其他产品线的同名版本（实证：`V2.5.x / V2.6` 的命中多属 **国内货运 N9M2.0** 火车，如 `13494_N9M2.0火车版本V2.6-260526`）。

**Step 6｜能浏览就别搜**
需要「这个版本目录里到底有哪些文件」时，最可靠的是**直接打开 `folderUrl` 看目录树**（服务端结构，不受召回影响），
比用关键词猜文件名稳得多。

### 3. 结论措辞规范（硬性）

| 情况 | 允许的写法 | 禁止的写法 |
|---|---|---|
| SOP 全部走完、每个分支都翻到 `hasMore=false` | 「本次检索范围内最高为 **V2.5.1**」 | 「最新就是 V2.5.1」「只有这些版本」 |
| 有一步没做完 / 翻不完 / 只跑了一种检索 | **第一句先写「待核实」**，再说「已看到最高为 X，是否还有更高未确认」，并点名缺哪个维度 | 先给「最新/最高」的断言，末尾补一句免责 |
| 用户报出更高版本号 | **立刻以用户事实为准**，拿该版本号去检索定位 | 拿旧结论辩解、要求用户证明 |

### 4. 自查清单（回答前逐条打勾）

- [ ] 关键词里带上了**版本号本体**，不只是产品名/「版本火车」
- [ ] 做过一轮**版本号维度的独立检索**，并翻到 `hasMore=false`
- [ ] 对候选集最高版本**向上试过一档**
- [ ] 没把 `filepath:` 当检索字段（它返回 0）
- [ ] 没把 `total` / `sort:'time'` 结果当全集或版本序
- [ ] 每个候选都核过 `folderPath`，排除了定制版与其他产品线同名版本
- [ ] 结论带「本次检索范围内」限定，或已写「待核实」

### 5. 反面样例（真实失误，供对照）

> ❌ 错误：用 `ADPlus2.0 版本火车` 搜了两次，得到 `total 50`，取相关度结果里最大版本号 V2.4.1，
> 断言「最高 V2.4.1」，还自行断言「未检索到 V2.5 / V2.6」。
> 实际 V2.5.1 早已发布于 `版本火车V2.5.1-Standard Version V2.5.1`（folderId 1168556），
> 只是关键词没带版本号、且从未做过版本号维度检索，所以没被召回。
>
> ✅ 正确：先用 `filename:(V2.5.1 AND ADplus2.0)` 直查版本号，或用 `ADPlus2.0 ReleaseNote` 收集全部候选版本号，
> 再对最高版本向上试一档，最后才下带范围限定的结论。

> 更早还有一次同型失误（1.0.55）：拿一次检索切片断言「最新是 V2.2.1」，而 V2.4.6 已存在。
> 两次错法完全相同：**采样结果 → 全称断言**。所以规则不是「多查一点」，而是
> **没有穷尽就没有「最新」，无法穷尽就写「待核实」**。

## 只在服务器检索（硬约束，优先级最高）

本技能**只用 `wjxt_search` 检索鸿翼文件系统**，以下做法一律禁止：

- ❌ 用**本地文件工具**（`file_search` / `list_dir` / `file_read` 等）在项目目录、`desktop/`、共享盘里
  「补充检索」同一个文件 —— 用户问的是**文件系统里的文件**，本地扫描纯属浪费一轮往返，
  还会抛出「本地 0 条」这种与问题无关的结论，把对话带偏；
- ❌ 提议「把本地目录路径发我，我在本地精确匹配」或其他绕开文件系统的替代方案；
- ❌ 用 `*`、空关键词之类当「探测查询」去试库是否为空 —— 只会得到 0 条与噪音。
  真需要放宽就换关键词、用 `mode`（工具内部还会自动拆词兜底）。

**结论只能来自 `wjxt_search` 的返回值**：

- 有命中 → 列清单（副本、修改时间、版本号、可点的目录/预览链接）；
- `count: 0` → 如实说「按这些关键词在文件系统里没命中」，给出 1~2 个更宽的关键词让用户选，
  **不要**断言「文件不存在」，**更不要**转去本地找；
- 只有用户**主动**说文件在本地（并给了本地路径）时，才用本地文件工具 —— 那是另一件事，与本技能无关。

## 登录态（重要）

**登录由应用负责：你不要索取账号密码、不要让用户复制 Cookie 或把地址扔到系统浏览器。**

edoc2（鸿翼）的会话与应用的 OA / 钉钉登录是**两件事**：分区里可能只有给 OA/SSO 用的票
（实测只有 `LtpaToken` / `checkToken`），edoc2 自己的会话得单独建立。

工具按下面顺序处理 —— **只有第 1 步是无感的，之后必须让用户自己选**：

1. **静默自愈**（无感，用户看不到任何窗口）：
   ① 静默 SSO（主进程带分区 cookie 请求登录入口）→ ② 隐藏窗口跑**站点 SSO 入口**把跳转链走完
   → ③ 仍失败则在返回登录入口前再跑一次隐藏窗口换票。
   > 2026-10-02 实证：SSO 换票必须在**活着的浏览器上下文**里走完「站点 → iam → 回跳站点」。
   > 隐藏窗口以前只等 2.5/3.5 秒就被销毁，跳转正停在 `iam…/idp/authCenter/authenticate`，票换不成；
   > 现在改为「轮询到落回站点才结束」，所以这步的成功率明显更高。
   > 说明：此前还有一步「用保存的账号密码静默续登」，已随「记住账号密码」机制一起移除
   > （站点没有这个接口，那是浏览器行为；应用不再保存任何口令）。
2. **询问用户选哪种登录方式**（1.0.48 起）：静默自愈失败时，工具**不再自作主张弹窗**，
   而是返回登录入口（在返回值的 `loginOptions` / `h5LoginUrl` / `qrLoginUrl` 里，
   另附**拼好的 `loginLinksMarkdown`**）。**照抄 `loginLinksMarkdown` 里的每一行**——
   它可能有一行（IAM 会话已过期）也可能是两行，**不要自己加链接、不要按记忆补第2 条**：
   - **账号密码登录**：`https://wj.streamax.com:9443/h5.html#login/index?returnUrl=%252Findex.html`
     （站点自带 H5 页，不经 IAM，白屏风险最低）
   - **扫码登录 / SSO 登录**（**仅当 `loginOptions` 里有第2 条时**）：`loginOptions[1].type === 'qrcode'`
     时是 IAM 二维码页（`…/ac/#/index?lck=…&entityId=edoc2`，一次性 `lck` 由应用现取，**不要自己拼、不要写死**）；
     `type === 'sso'` 时是**站点 SSO 入口**（`…/sso/auth/goToLoginPage`），打开后由站点自动跳转完成登录，
     **通常不会显示二维码** —— 这时**别把它叫「扫码登录」**，否则用户以为会看到二维码。
   - **只有一条时的原因**：`iamSessionAlive === false` 表示统一身份（IAM）会话已过期，
     此时 SSO 入口只会停在 `iam…/idp/authCenter/authenticate` 跳转中途，**在应用内窗口里是一片空白**
     （用户反馈「点 SSO 登录就是白屏」）。所以应用**故意不再给这个入口**，只给账号密码方式。
     这时**不要说「点第二个链接更快」之类的话**，也不要重复给 SSO 地址。
   - **链接必须写成 Markdown 超链接**，不要输出裸 URL：直接照抄返回里的 `loginLinksMarkdown`
     （形如 `[账号密码登录](…)` / `[扫码登录](…)`），用户看到的是可点文字而不是一长串地址。
   参考话术（两个入口时）：
   > 鸿翼文件系统（企业内容库）当前没有可用的登录态，已尝试无感恢复但未成功。请选一种方式登录
   > （点链接即可，会在应用内窗口打开；**登录成功后窗口会显示「登录成功」再自动关闭**）：
   > 1. [账号密码登录](<链接>) —— 站点自带 H5 页，不经 IAM
   > 2. [扫码登录](<链接>) —— IAM 二维码页 / 站点 SSO 入口
   > 登录完成后回一句「已登录」，我就立刻重试刚才的查询。（不要用系统浏览器打开：不共享登录态。）
   只有一条时把第2 行去掉即可（应用通常已经在 `message` 里写明了原因，照抄即可）。
3. **用户点开链接后**：窗口由应用打开并共享登录分区；登录成功 → 窗口先显示「✅ 登录成功，正在返回应用…」
   再自动关闭，你只需等用户说「已登录」，然后重试同一个查询（不要反复重试工具）。
   > 若返回里出现 `error: 'WJXT_SESSION_RESTORED'` 或 `healed: true`：说明**登录态已自动恢复**，
   > 直接重试原查询即可，**不要再让用户去登录**。
4. **窗口是空白页** → 站点 SSO 入口返回的是一份 1251 字节的**跳转壳页**（日志实证），
   在应用内窗口里没有可见内容；窗口顶部会显示一条提示条说明正在自动登录。
   若长时间空白：让用户换用**账号密码**方式（H5 页，不经 IAM），或先在应用内重新完成一次 OA 登录再试；
   **不要**反复重试工具，也**不要**建议「用系统浏览器打开」（系统浏览器与应用不共享登录态，扫了也没用）。

> ⚠️ SSO 页会跳到 IAM 的「AC 登录页」（`iam.streamax.com/ac/#/index?lck=…&entityId=edoc2`）。
> 实测（真实分区，2026-09-23）：**IAM 侧的 `route/SESSION/usk` cookie 都在**，但该页仍显示
> 「用户登录 / 扫码 / 密码」，即 edoc2 换票所需的 **IAM AC 登录态**不成立；且该页在应用内窗口里
> 可能**渲染为空（白屏）**、或不停在 `wj` 与 `iam` 之间跳转。
> 所以备份通道改用 **H5 登录页**（`h5.html#login/index`，账号密码，**完全不经过 IAM**）。
> 看到 `NEED_RELOGIN` 时**别**让用户去点 SSO/IAM 地址。
>
> 💡 实测（2026-09-23）：**edoc2 不依赖 IAM 的 AC 登录** —— 应用重启后会从 OA 会话备份恢复
> `LtpaToken` 等票并注入分区（日志 `[oaCookie] inject … +12 cookies`），edoc2 检索随即成功
> （`[search] strategy=word hit 10/10`）。所以遇到「文件系统未登录」时，**先让用户重启应用
> （或重新完成一次 OA 登录）**往往就够了，比引导他去输账号密码更快；H5 通道是再往后的兜底。

## 标准流程（必须遵守）

1. **先搜清单，再下载**：先调 `wjxt_search` 拿编号清单（检索**只在服务器**做，见上一节的硬约束）。
   想更准可以用描述里的型号/版本做关键词；一次搜不到就换关键词再搜一次，不要凭记忆编造文件名，
   也不要改用本地文件工具「补充检索」。
2. **命中多条时必须先让用户确认**：把清单按编号列给用户（编号、文件名、大小、类型），让用户说「下第 2 个」「全下」或给筛选条件（如「只要 Release 版」）。**不要**在多条命中时自行挑一个下载。
   - 唯一例外：用户已经点名了具体文件名/版本，且清单里只有一条符合，可直接下。
3. **下载目录**：
   - 用户明确给了目录 → 直接用（可以是绝对路径，也可以是工作区别名，如 `desktop/下载`、`工作区/资料`）。
   - 用户**没说**目录 → 先问一句「下载到哪个目录？」，**不要**默认写到某个位置。
   - 目录不存在会自动创建；同名文件会自动改名成「名称(1).ext」，**不会覆盖**已有文件。
4. **单次不要拉太多**：`wjxt_download` 支持一次传多个 `fileGuid`，但超过 10 个时先和用户确认数量与目录。
5. **下载后校验并汇报**：调用 `wjxt_download` 时，把搜索结果里的 `size` 按顺序放进 `sizes` 参数（与其一一对应），
   工具会做**文件头校验**（PK/PDF/OLE2；拿到 HTML 说明是登录页，会被判成登录态失效）与**精确字节数比对**，
   返回 `kind` 与 `sizeMatched`。把「文件名 + 字节数 + 保存路径 + 校验结论」列给用户；
   若 `sizeMatched=false`，明确提示可能不完整并要求重试。
6. **判断「哪份/哪个版本最新」**：**不要凭一份清单的印象下结论** —— 一律按上面
   「版本查询方法论」的 **Step 1~6** 走完（含版本号维度的独立检索、向上试一档、产品线归属核对），
   再按「结论措辞规范」的三档措辞作答（走完 → 带「本次检索范围内」；缺维度 → 第一句「待核实」）。
   把候选按**版本号**顺序给用户，并说明各自版本号与差异。
7. **搜不全时先换手段，再下结论**：`ADPLUS` 这类宽词只能命中一部分；
   想按片段查用 `mode: 'contains'`，想按时间/创建者/类型限定用 `query`（见上表的字段与区间写法）。

## 输出格式

**搜索清单固定用一张表**，列的**顺序与名称都不要改**：

| 编号 | 文件名 | 大小 | 修改时间 | 目录 | 创建人 | 预览/下载 |
|---|---|---|---|---|---|---|

- **文件名**：链接文字＝文件名，href＝`previewUrl`。
- **大小**：`size` 转成 KB/MB；**修改时间**：`modifyTime`（已是 `YYYY-MM-DD HH:mm`）；**创建人**：`creatorName`。
- **目录**：链接文字用 **`folderPath`**（服务端 `relativePath`，形如 `企业文档库/AD PLUS 2.0/版本发布`），
  href 用 `folderUrl` —— 写成 `[企业文档库/AD PLUS 2.0/版本发布](folderUrl)`。
  **不要**用 `path`（那是 `1\913\921\…` 的数字 id 串，用户看不懂），也不要写成「浏览该目录」这种无信息量的文字；
  `folderPath` 为空时才退回落数字路径。
- **目录必须在「任何地方」都是可点链接，不只是结果表里**（用户实测踩过）：返回里还有 `folders[]`
  —— 本次结果覆盖到的目录去重清单，每项自带现成的 `markdown`。
  **开头「资料主要分布在以下 N 个目录」这类归纳表、多轮追问后的总结、结论里给的定位建议，凡写到目录一律照抄
  `folders[].markdown`**，**禁止**写成点不开的纯文本路径（模型自己拼目录链接必然拼错，所以给了现成片段）。
- **最后一列固定写成 `[预览](previewUrl) / [下载](downloadUrl)`** —— **两个链接都要给**：
  - **预览**：在应用内窗口打开站点预览页查看文件，**不下载**；
  - **下载**：弹「另存为」对话框，把**原始文件**存到用户选的路径（默认文件名就是这份文件的真实文件名，含后缀）。
  - ⚠️ 不要只写一个「预览/下载」，也不要把同一个 `previewUrl` 同时当预览和下载用 ——
    那会让用户点「下载」时拿到一份**文件名错、没有后缀**的文件（应用会按链接文案当文件名）。
- 下载结果（`wjxt_download`）：逐条「✅ 文件名 → 路径（大小）」，失败项单独列出并说明原因。
- 不要输出服务端原始 JSON；不要暴露 Cookie、token、签名 URL 的内部参数（给路径即可）。

## 效率要求（硬性）

- **一次 `wjxt_search` 调用内部已经会自动换写法**（原模式 → 子串 → 拆词 → 范围前缀），
  返回里的 `strategy` 就是命中的那条、`note` 会说明「原查询没命中、已自动改用 X 命中 N 条」。
  看到 `note` 就**直接用结果**，不要自己再换词重试。
- **中文资料词会自动扩展英文写法**（规格书→Specification/Spec/Datasheet、证书→Certificate、报告→Report…）
  并入**文件名**检索，且结果按「文件名命中优先」重排 —— 文件名里就带关键词的排在只被正文命中的前面。
  所以中文关键词也能搜到英文命名的文件；但搜具体型号资料时，**关键词带上型号 + 英文资料词更准**
  （如「DS100 Specification」）；要严格限定文件名时用 `query` 传 `filename:(词1 AND 词2)`。
- **最多调用 `wjxt_search` 两次**（针对「换个关键词再碰碰运气」式重试）：第二次只允许在
  「第一次返回 0 条」或「用户改了口径」时使用；然后必须给出结论（找到哪几份 / 没找到）。
  但「版本查询方法论」SOP 要求的**版本号维度独立检索（Step 2）、候选集收集（Step 3）、向上试一档（Step 4）**
  以及它们的翻页（`from`/`size`）**都不计入这条限制** —— 那是验证动作、不是换词碰运气
  （此前**两次**都拿这条当理由跳过验证，属于规则被误用）；
  总量仍要克制（一般不超过 5~6 次），每次都有明确目的，禁止无目的地连续翻页；
  实在翻不完就**先写「待核实」**，别硬下一个自己都不确定的结论。
- 拿到清单后**一次性**把结论给全：目标文件、所有副本（时间/大小/目录/创建人）、同族版本的先后顺序。
  不要分多轮「我再补两轮查询」。
- 含数字/标点的长片段（如 `M0010_V3_2.4.6`）不要用 `mode: 'contains'`：通配符在该字段上对这类片段不敏感，
  用 `mode: 'word'` 或干脆只给一个有区分度的短片段（如 `RC26042090`）。

## 常见错误与处置

| 现象 | 含义 | 你要做什么 |
|---|---|---|
| `WJXT_NO_SESSION` | 应用内没有可用的 edoc2 会话：服务端返回未登录信封 `{"url":"…/sso/auth/goToLoginPage","errorCode":"ErrorCode4"}`（HTTP 200 的合法 JSON）。**不是「0 条」**；也可能是 `Preview/GetPreviewPara` 回了 `{"status":"error","data":{"fileUrl":null…}}` | 工具已先试过**静默自愈**（静默 SSO / 隐藏窗口），都失败 → **不要再提「记住账号密码」**（该机制已移除）。请**询问用户**想用哪种方式，并把返回 `loginLinksMarkdown` 里的链接给他（**可能只有一条**：IAM 会话过期时应用会只给账号密码，因为 SSO 入口那时必白屏）—— **必须写成 Markdown 超链接**，点开在应用内窗口打开，登录成功会显示「登录成功」再自动关窗，登录完再重试原查询 |
| `NEED_RELOGIN` | 登录态已失效（同上，只是形态不同） | 同上：照抄 `loginLinksMarkdown` 询问并给出登录链接（可能只有一条）；不要自己想办法登录，也不要只丢一个 SSO/IAM 地址让用户猜，更不要在应用没给 SSO 入口时自行补一个 |
| `WJXT_SESSION_RESTORED`（或返回里 `healed: true`） | 登录态**已自动恢复**（隐藏窗口把 SSO 链跑完，或取 lck 那次导航顺带换了票） | **立刻用相同参数重试原查询**，不要让用户去登录，也不要把这条错误码转述给用户 |
| `WJXT_SERVER_ERROR` | 服务端返回了业务错误码（非 ErrorCode4） | 把 errorCode 原文转给用户/开发，不要反复重试 |
| `WJXT_BAD_REQUEST` | 服务端拒绝（来源/会话异常） | 提示用户重新登录后再试；不要反复狂试 |
| `WJXT_TIMEOUT` | 内网抖动或服务慢 | 告诉用户超时并重试一次；仍失败就如实说明 |
| `WJXT_HTTP_404` | 接口 404（工具已先做会话预热、并强制重做一次预热后重试，仍失败） | 说明服务端/网关确实不可用，稍后再试；不要连续狂试 |
| `WJXT_HTTP_5XX` | 服务端异常 | 说明服务端 5xx，稍后再试 |
| `WJXT_BAD_RESPONSE` | 返回的不是预期 JSON（服务端契约变化/真异常） | 把 message 里的 status / content-type / body 片段原样转给用户，便于定位；不要反复重试 |
| `PATH_OUTSIDE_ROOT` | 目标目录不在已授权工作区 | 引导用户用 `open_folder` 打开该目录（或改到自己工作区内的目录）后再下载 |
| 无结果（`ok:true, count:0`） | 关键词没命中，或该账号/范围内确实看不到这份文件（工具已自动去掉范围前缀条件放宽重搜过一次） | 先换 1~2 个更宽的关键词（型号前缀、版本号段）再搜；仍无则如实说没找到，**不要**编造文件名、也不要说「文件不存在」；可以提醒用户：换词、或确认这份文件是否在该文件系统的权限范围内 |

## 禁止事项

- 不要使用、也不要建议安装 `agent-browser`、Playwright、Chrome 或任何浏览器自动化工具：本技能在应用内执行，
  请求由应用自己发起（隐藏窗口的页面上下文），无需任何外部浏览器。
- 不要索取或输出账号、密码、Cookie、token。
- **不要再提「记住账号密码 / 自动续登」**：站点没有这个接口（那是浏览器行为），应用也不保存口令；
  1.0.48 起该机制已整体移除，登录时不会再出现保存提示，你也不要建议用户去找它。
- **不要把「预览」与「下载」合并成一个链接**（如 `[下载/预览](…)`）：两者是两个独立入口 ——
  「预览」在应用内窗口查看、「下载」弹「另存为」存原始文件。每条结果都带 `markdown` 字段（拼好的现成片段），
  直接照抄即可；**两个链接都要给**。
- **不要把登录链接写成裸 URL**（用户看到的是一长串地址，不好点也不好看）：返回里有拼好的
  `loginLinksMarkdown`，直接照抄，输出形如 `[账号密码登录](…)` / `[扫码登录](…)` 的可点文字。
- **不要自己补登录链接**：返回里只有一条时就只给一条（IAM 会话过期时 SSO 入口必白屏，
  应用据此有意不提供；自行补一个 SSO 地址只会让用户点进去看到空白页）。
- 不要用搜索接口的输出替代实际文件内容：用户要看文件内容时，下载后用 `file_read` 读取。
- 不要在未确认的情况下批量下载超过 10 个文件。
