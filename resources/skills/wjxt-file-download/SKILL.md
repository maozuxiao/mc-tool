# 鸿翼文件系统：搜索与原始文件下载

## 适用范围

用户在对话里提到「文件系统 / 鸿翼 / 弘毅 / 企业内容库」，或要求按关键词找一份文件、把某个文档下载到本地时，用本技能的两个工具完成：

| 工具 | 作用 |
|---|---|
| `wjxt_search` | 关键词检索（文件名 + 正文内容），返回编号清单：编号 / 文件名 / 扩展名 / 字节数 / **修改时间** / **版本号** / 目录路径 / `fileGuid`，以及给人点的 **`previewUrl`（预览）/ `downloadUrl`（下载）** |
| `wjxt_download` | 按 `fileGuid` 下载**原始文件**到指定目录（不转码、不改格式，字节数与服务器一致）；回报每个文件的**文件头类型**与**字节数是否与期望一致** |

> 两种「拿到文件」的方式分工：**清单里的「预览」/「下载」链接给用户自己点** ——
> 「预览」在应用内窗口打开查看（不下载），「下载」弹「另存为」把原始文件存到用户选的路径；
> `wjxt_download` 只在**用户明确要求「存到某个目录」**时用（它由 AI 直接写盘并做校验）。

> 查询串不带范围前缀 `(filepath:(1) OR masterfilepath:(1))` —— 实测带上它会把结果筛成空（HTTP 200 但 0 条）。
>
> **检索能力（复用上游「增强搜索」脚本的用法）**：
>
> | 参数 | 取值 | 用途 |
> |---|---|---|
> | `mode` | `word`（默认）/ `contains` / `exact` | `word` 分词匹配、大小写不敏感；`contains` 按 `*关键词*` 子串匹配（查文件名片段，如 `M0010_V3_2.4.6`，比 word 慢）；`exact` 整串精确匹配 |
> | `sort` | `score`（默认）/ `time` / `size` / `name` | **问「哪个最新」就用 `time`**（按修改时间倒序），`size` 从大到小，`name` 按文件名升序。**服务端排序已做自动兜底**：本部署对服务端 `modifyTime` 排序会**静默返回空结果集**（曾有整轮查询因此误判成「0 条/文件不存在」），工具遇到 0 条会自动改回相关度排序并在**本地**按该键排好，返回里 `note` 会说明 —— 直接用结果，**不要**因为看到 `sortMode: local:time` 就再折腾 |
> | `from` | 数字 | 分页偏移：`total` 大于返回条数时用它翻页（返回里带 `hasMore`） |
> | `query` | ES 查询串 | 高级用法，字段：`filename` / `filecontent` / `extName` / `creatorName` / `modifyTime` / `filepath`。例：`filename:(HY_ADPLUS2.0) AND filename:(Train OR 火车)`、`modifyTime:[2026-01-01 TO 2026-12-31]` |
>
> 注意：**通配符大小写敏感**（实测 `*RED*` 匹配不到 `Red.png`）。`mode=contains` 时工具已自动 OR 出大小写变体；手写 `query` 时需自己注意。

## 只在服务器检索（硬约束，优先级最高）

本技能**只用 `wjxt_search` 检索鸿翼文件系统**，以下做法一律禁止：

- ❌ 用**本地文件工具**（`file_search` / `list_dir` / `file_read` 等）在项目目录、`desktop/`、共享盘里
  「补充检索」同一个文件 —— 用户问的是**文件系统里的文件**，本地扫描纯属浪费一轮往返，
  还会抛出「本地 0 条」这种与问题无关的结论，把对话带偏；
- ❌ 提议「把本地目录路径发我，我在本地精确匹配」或其他绕开文件系统的替代方案；
- ❌ 用 `*`、空关键词之类当「探测查询」去试库是否为空 —— 只会得到 0 条与噪音。
  真需要放宽就换关键词、用 `mode`（工具内部还会自动拆词兜底）。

**结论只能来自 `wjxt_search` 的返回值**：

- 有命中 → 列清单（副本、修改时间、版本号、可点的目录/预览链接）；
- `count: 0` → 如实说「按这些关键词在文件系统里没命中」，给出 1~2 个更宽的关键词让用户选，
  **不要**断言「文件不存在」，**更不要**转去本地找；
- 只有用户**主动**说文件在本地（并给了本地路径）时，才用本地文件工具 —— 那是另一件事，与本技能无关。

## 登录态（重要）

**登录由应用负责：你不要索取账号密码、不要让用户复制 Cookie 或把地址扔到系统浏览器。**

edoc2（鸿翼）的会话与应用的 OA / 钉钉登录是**两件事**：分区里可能只有给 OA/SSO 用的票
（实测只有 `LtpaToken` / `checkToken`），edoc2 自己的会话得单独建立。

工具按下面顺序**自动**处理，你只需如实转达结论、并在需要时让用户去点一下窗口：

1. **静默自愈**：静默 SSO + 隐藏窗口把站点首页跑一遍。会话还有效时用户**看不到任何窗口**，搜索直接出结果。
2. **已保存账号的自动续登**：用户此前选过「记住账号密码」时，工具用保存的账号密码**静默**登录，同样无感。
3. **H5 账号密码登录窗口**：以上都不行时，工具会弹出**可见的【登录文件系统（账号密码）】窗口**
   （站点自带的 H5 登录页）。这时告诉用户：「已在应用内打开**登录文件系统（账号密码）**窗口，
   请在里面用**账号密码**登录一次；成功后窗口会自动关闭并跳回文件系统首页，然后我立刻重试同一个查询」。
   可选提示：窗口登录时若弹出「记住账号密码」，选了以后就会自动续登、不再打扰。
4. **窗口是空白页** → 最可能是站点 SSO 跳到了 IAM 认证页、而该页在应用内窗口里渲染为空（不是网络问题）：
   让用户改用窗口里的**账号密码**方式（H5 页，不经 IAM），或先在应用内重新完成一次 OA 扫码登录再试；
   **不要**反复重试工具。

> ⚠️ SSO 页会跳到 IAM 的「AC 登录页」（`iam.streamax.com/ac/#/index?lck=…&entityId=edoc2`）。
> 实测（真实分区，2026-09-23）：**IAM 侧的 `route/SESSION/usk` cookie 都在**，但该页仍显示
> 「用户登录 / 扫码 / 密码」，即 edoc2 换票所需的 **IAM AC 登录态**不成立；且该页在应用内窗口里
> 可能**渲染为空（白屏）**、或不停在 `wj` 与 `iam` 之间跳转。
> 所以备份通道改用 **H5 登录页**（`h5.html#login/index`，账号密码，**完全不经过 IAM**）。
> 看到 `NEED_RELOGIN` 时**别**让用户去点 SSO/IAM 地址。

## 标准流程（必须遵守）

1. **先搜清单，再下载**：先调 `wjxt_search` 拿编号清单（检索**只在服务器**做，见上一节的硬约束）。
   想更准可以用描述里的型号/版本做关键词；一次搜不到就换关键词再搜一次，不要凭记忆编造文件名，
   也不要改用本地文件工具「补充检索」。
2. **命中多条时必须先让用户确认**：把清单按编号列给用户（编号、文件名、大小、类型），让用户说「下第 2 个」「全下」或给筛选条件（如「只要 Release 版」）。**不要**在多条命中时自行挑一个下载。
   - 唯一例外：用户已经点名了具体文件名/版本，且清单里只有一条符合，可直接下。
3. **下载目录**：
   - 用户明确给了目录 → 直接用（可以是绝对路径，也可以是工作区别名，如 `desktop/下载`、`工作区/资料`）。
   - 用户**没说**目录 → 先问一句「下载到哪个目录？」，**不要**默认写到某个位置。
   - 目录不存在会自动创建；同名文件会自动改名成「名称(1).ext」，**不会覆盖**已有文件。
4. **单次不要拉太多**：`wjxt_download` 支持一次传多个 `fileGuid`，但超过 10 个时先和用户确认数量与目录。
5. **下载后校验并汇报**：调用 `wjxt_download` 时，把搜索结果里的 `size` 按顺序放进 `sizes` 参数（与其一一对应），
   工具会做**文件头校验**（PK/PDF/OLE2；拿到 HTML 说明是登录页，会被判成登录态失效）与**精确字节数比对**，
   返回 `kind` 与 `sizeMatched`。把「文件名 + 字节数 + 保存路径 + 校验结论」列给用户；
   若 `sizeMatched=false`，明确提示可能不完整并要求重试。
6. **判断「哪份/哪个版本最新」**：直接把 `sort` 设成 `time` 让服务端按修改时间倒序返回，
   再结合 `modifyTime`（已转成 `YYYY-MM-DD HH:mm`）与 `lastVerNumStr` —— **不要**凭文件名里的数字猜。
   把候选按时间倒序列给用户，并说明各自版本号与差异。
7. **搜不全时先换手段，再下结论**：`ADPLUS` 这类宽词只能命中一部分；
   想按片段查用 `mode: 'contains'`，想按时间/创建者/类型限定用 `query`（见上表的字段与区间写法）。

## 输出格式

**搜索清单固定用一张表**，列的**顺序与名称都不要改**：

| 编号 | 文件名 | 大小 | 修改时间 | 目录 | 创建人 | 预览/下载 |
|---|---|---|---|---|---|---|

- **文件名**：链接文字＝文件名，href＝`previewUrl`。
- **大小**：`size` 转成 KB/MB；**修改时间**：`modifyTime`（已是 `YYYY-MM-DD HH:mm`）；**创建人**：`creatorName`。
- **目录**：链接文字用 **`folderPath`**（服务端 `relativePath`，形如 `企业文档库/AD PLUS 2.0/版本发布`），
  href 用 `folderUrl` —— 写成 `[企业文档库/AD PLUS 2.0/版本发布](folderUrl)`。
  **不要**用 `path`（那是 `1\913\921\…` 的数字 id 串，用户看不懂），也不要写成「浏览该目录」这种无信息量的文字；
  `folderPath` 为空时才退回落数字路径。
- **最后一列固定写成 `[预览](previewUrl) / [下载](downloadUrl)`** —— **两个链接都要给**：
  - **预览**：在应用内窗口打开站点预览页查看文件，**不下载**；
  - **下载**：弹「另存为」对话框，把**原始文件**存到用户选的路径（默认文件名就是这份文件的真实文件名，含后缀）。
  - ⚠️ 不要只写一个「预览/下载」，也不要把同一个 `previewUrl` 同时当预览和下载用 ——
    那会让用户点「下载」时拿到一份**文件名错、没有后缀**的文件（应用会按链接文案当文件名）。
- 下载结果（`wjxt_download`）：逐条「✅ 文件名 → 路径（大小）」，失败项单独列出并说明原因。
- 不要输出服务端原始 JSON；不要暴露 Cookie、token、签名 URL 的内部参数（给路径即可）。

## 效率要求（硬性）

- **一次 `wjxt_search` 调用内部已经会自动换写法**（原模式 → 子串 → 拆词 → 范围前缀），
  返回里的 `strategy` 就是命中的那条、`note` 会说明「原查询没命中、已自动改用 X 命中 N 条」。
  看到 `note` 就**直接用结果**，不要自己再换词重试。
- **最多调用 `wjxt_search` 两次**。第二次只允许在「第一次返回 0 条」或「用户改了口径」时使用；
  然后必须给出结论（找到哪几份 / 没找到），不要为「再确认一下最新版本」反复追加查询 ——
  要最新的直接用 `sort: 'time'`，一次返回里就带 `modifyTime` 与 `lastVerNumStr`。
- 拿到清单后**一次性**把结论给全：目标文件、所有副本（时间/大小/目录/创建人）、同族版本的先后顺序。
  不要分多轮「我再补两轮查询」。
- 含数字/标点的长片段（如 `M0010_V3_2.4.6`）不要用 `mode: 'contains'`：通配符在该字段上对这类片段不敏感，
  用 `mode: 'word'` 或干脆只给一个有区分度的短片段（如 `RC26042090`）。

## 常见错误与处置

| 现象 | 含义 | 你要做什么 |
|---|---|---|
| `WJXT_NO_SESSION` | 应用内没有可用的 edoc2 会话：服务端返回未登录信封 `{"url":"…/sso/auth/goToLoginPage","errorCode":"ErrorCode4"}`（HTTP 200 的合法 JSON）。**不是「0 条」**；也可能是 `Preview/GetPreviewPara` 回了 `{"status":"error","data":{"fileUrl":null…}}` | 工具已先试过静默登录（静默 SSO / 隐藏窗口 / 保存过的账号密码），都失败才弹出**【登录文件系统（账号密码）】窗口**（成功后自动关闭并跳回首页）。告诉用户：**在那个窗口里用账号密码登录一次**，然后重试原查询 |
| `NEED_RELOGIN` | 登录态已失效（同上，只是形态不同） | 同上：H5 登录窗口已弹出，用户登录后重试；不要自己想办法登录、也不要让用户点 SSO 地址（会白屏） |
| `WJXT_SERVER_ERROR` | 服务端返回了业务错误码（非 ErrorCode4） | 把 errorCode 原文转给用户/开发，不要反复重试 |
| `WJXT_BAD_REQUEST` | 服务端拒绝（来源/会话异常） | 提示用户重新登录后再试；不要反复狂试 |
| `WJXT_TIMEOUT` | 内网抖动或服务慢 | 告诉用户超时并重试一次；仍失败就如实说明 |
| `WJXT_HTTP_404` | 接口 404（工具已先做会话预热、并强制重做一次预热后重试，仍失败） | 说明服务端/网关确实不可用，稍后再试；不要连续狂试 |
| `WJXT_HTTP_5XX` | 服务端异常 | 说明服务端 5xx，稍后再试 |
| `WJXT_BAD_RESPONSE` | 返回的不是预期 JSON（服务端契约变化/真异常） | 把 message 里的 status / content-type / body 片段原样转给用户，便于定位；不要反复重试 |
| `PATH_OUTSIDE_ROOT` | 目标目录不在已授权工作区 | 引导用户用 `open_folder` 打开该目录（或改到自己工作区内的目录）后再下载 |
| 无结果（`ok:true, count:0`） | 关键词没命中，或该账号/范围内确实看不到这份文件（工具已自动去掉范围前缀条件放宽重搜过一次） | 先换 1~2 个更宽的关键词（型号前缀、版本号段）再搜；仍无则如实说没找到，**不要**编造文件名、也不要说「文件不存在」；可以提醒用户：换词、或确认这份文件是否在该文件系统的权限范围内 |

## 禁止事项

- 不要使用、也不要建议安装 `agent-browser`、Playwright、Chrome 或任何浏览器自动化工具：本技能在应用内执行，
  请求由应用自己发起（隐藏窗口的页面上下文），无需任何外部浏览器。
- 不要索取或输出账号、密码、Cookie、token。
- 不要用搜索接口的输出替代实际文件内容：用户要看文件内容时，下载后用 `file_read` 读取。
- 不要在未确认的情况下批量下载超过 10 个文件。
