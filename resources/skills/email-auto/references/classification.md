# 邮件分类与紧急度口径

## 一、十类（默认口径，先分类再谈紧急度）

| 类型 | 判定要点 | 典型动作 |
|------|----------|----------|
| 客户询盘 | 询问产品能力、参数、适配、案例，尚无明确项目 | 概述能力 + 要参数/场景 |
| 报价 / 议价 | 出现价格、折扣、预算、PO 金额 | **需人工处理**（销售/商务） |
| 样机 / 演示申请 | 要样机、要 demo、要测试机 | 确认型号数量 + 走流程 |
| 订单 / 交付跟进 | 交期、发货、物流、催单 | 查交付进度后回复 |
| 合同 / 回款 | 合同条款、盖章、发票、付款 | **需人工处理** |
| 渠道合作 | 代理、分销、区域合作、OEM | 转商务，勿承诺政策 |
| 展会 / 活动 | 邀请、报名、展位、议程 | 转市场 |
| 客户投诉 | 明确表达不满、故障未解决、要求赔偿 | 高优先，先共情再给行动 |
| 内部协同 | 同事、跨部门、流程审批 | 按内部流程 |
| 无需处理 | 系统通知、订阅、自动回执、营销群发 | 一句话带过 |

判定顺序：**先看是否有金额/合同/承诺**（→ 需人工处理），再看是否故障投诉（→ 高），最后看是否业务机会。拿不准时按"更保守"的那一类归。

## 二、紧急度

- **high**：生产中断 / 客户已上线受阻 / 明确投诉或索赔 / 承诺今天到期 / 大客户明确催办。
- **medium**：需要回复但不阻塞业务；含明确问题待答；3 个工作日内需回。
- **low**：知会类、资料索取、无明确时间要求。

判断只看三个信号：**是否阻塞客户业务**、**是否有明确时限词**（ASAP、today、this week、deadline）、**是否已升级**（抄送领导、第二次追问）。

## 三、待回复判定（needs_reply）

满足任一即视为需要回复：

1. 正文有问句且收件人里有你；
2. 明确请求动作（send / confirm / provide / check）；
3. 投诉或负面情绪；
4. 你是唯一收件人且邮件非通知类。

不需要回复：纯通知（`no-reply@`、系统回执）、已在同线程里由他人答复、群发营销。

## 四、输出模板

```
## 概览
共 12 封（未读 5 封），2026-10-20 ~ 2026-10-27

## 分类统计
客户询盘 3 · 订单交付 2 · 客户投诉 1 · 内部协同 4 · 无需处理 2

## 待回复（按紧急度）
1. [high] Kentkart / Ersan Doru — 客户投诉 — 备份与远程接入受阻 — 建议今天 18:00 前回复
2. [medium] ABC / John — 客户询盘 — 询问 DS100 是否支持 4G — 建议 2 个工作日内
3. [low] 内部 / 李四 — 内部协同 — 需求排期确认

## 无需处理
系统告警 2 封、订阅摘要 1 封
```

要给出**发件人 + 公司**、**一句话事项**、**紧急度**、**建议回复时限**四项，缺一项都算不合格。
